# MediaLAB — итоговый комплект проекта

Учебный проект по модулю «Системный анализ и разработка сложных информационных систем». Команда: Семен Саломанов, Павел Шаравин.

## Как запустить API на Mac/Linux

Откройте терминал в этой папке (где находится `README.md`), затем выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r api/requirements.txt
python -m uvicorn api.main:app --reload
```

Swagger UI: http://127.0.0.1:8000/docs. Машиночитаемая спецификация запущенного API: http://127.0.0.1:8000/openapi.json.

На Windows используйте `py -m venv .venv`, `.venv\Scripts\activate` и затем `python -m pip install ...`, `python -m uvicorn ...`.


## Как выполнить запросы в Postman

1. Запустите API по инструкции выше (терминал оставьте открытым).
2. В Postman выберите **Import** и файл `postman/MediaLAB.postman_collection.json`.
3. Выполните `GET /equipment` — получите три демонстрационные единицы техники.
4. Выполните `POST /bookings` — заявка будет создана, ее `id` автоматически сохранится как переменная `booking_id`.
5. Затем выполните `GET /bookings/{booking_id}` и `POST /bookings/{booking_id}/decision` (роль `admin-1`, решение `approve`).
6. Выполните `POST /bookings/{booking_id}/issue` и `POST /bookings/{booking_id}/return` (администратор). При возврате можно выбрать `good` или `damaged`.

Коллекция использует `student-1` и `admin-1`, рассчитывает даты на основе текущего времени с UTC-смещением и передает `X-Actor-Id`. Если заявка конфликтует с предыдущей, выберите другую технику либо удалите локальную базу `api/medialab.db` **только после остановки сервера** и запустите его заново для чистой демонстрации.

**Для выдачи** начало бронирования должно находиться не далее чем через 15 минут от текущего момента; коллекция создает период с началом через 10 минут.

## Тесты

Из корня комплекта (в активном окружении):

```bash
python -m pytest tests/test_api.py -v
```

Тесты работают с независимыми временными базами и не портят демонстрационные данные. 
## Граница между проектом и прототипом

**Целевая архитектура на C1/C2:** Telegram-бот, панель администратора, сервер FastAPI, PostgreSQL, Celery/Redis и объектное хранилище.

**Что реализовано:** FastAPI + SQLite с 12 операциями, проверками ролей через демонстрационный заголовок, управлением заявками, выдачей/возвратом, учетом состояния техники и ручным вызовом проверки просрочек.
